# Aetherion Online — Laporan Milestone 1 (Core Engine & Multiplayer)

Status: **M1 selesai dan teruji**, dengan penyimpangan tech stack yang dijelaskan di bawah. M2–M9 belum dikerjakan.

## 1. Yang dibangun

| Area | Implementasi |
|---|---|
| Akun | Registrasi/login, hash scrypt ber-salt, token sesi acak 256-bit (hanya hash SHA-256 yang disimpan), logout, rate limit per IP |
| Karakter | Buat/pilih karakter, 6 job bisa dipilih, tampilan dasar (kulit, gaya rambut, warna rambut, warna pakaian), maksimum 4 per akun, tersimpan di PostgreSQL |
| Dunia | 2 zona terhubung portal: Eldoria (kota) dan Verdant Reach (hutan). Peta dibangkitkan deterministik dari seed, kode yang sama dipakai server dan klien |
| Simulasi | Server otoritatif, 20 tick/detik, loop dengan koreksi drift. Klien hanya mengirim arah input; posisi dihitung server |
| Anti-cheat dasar | Anggaran input per tick (speed hack tidak menambah kecepatan), validasi input, batas ukuran pesan 1 KB, batas laju pesan, satu sesi aktif per karakter |
| Jaringan | Interest management dengan spatial grid; snapshot delta (add / move / remove); pemain diam hanya menerima heartbeat 1×/detik |
| Klien | Prediksi sisi klien, rekonsiliasi server, interpolasi pemain lain (tunda 100 ms), render kanvas dengan cache chunk tile dan object pooling |
| Sosial | Chat zona dengan rate limit dan sanitasi |
| Koneksi | Reconnect otomatis; entitas dipertahankan 10 detik sehingga pemain lanjut di tempat |
| Persistensi | Simpan saat keluar, autosave batch tiap 30 detik (satu query untuk semua pemain), simpan saat shutdown. Tidak ada tulis DB per gerakan |
| Matchmaking | Channel per zona; zona penuh (150) membuka channel baru |
| HUD | Potret, nama, level, zona, minimap, chat, ping/FPS |
| Tanpa energi | Tidak ada sistem energi/stamina dalam bentuk apa pun |

## 2. Penyimpangan dari tech stack yang diminta

Sandbox build tidak punya akses jaringan untuk `npm install`, jadi paket berikut **tidak dipakai**. Masing-masing diganti implementasi yang benar-benar dijalankan dan diuji, di balik antarmuka sempit agar bisa ditukar.

| Diminta | Dipakai di M1 | Titik tukar |
|---|---|---|
| Phaser 3 | Renderer Canvas 2D sendiri | `client/src/game/Game.ts` (bagian render) dan `art.ts` |
| Colyseus | Room server sendiri di atas `ws` | `server/src/game/World.ts`, gateway di `server/src/app.ts` |
| Prisma | Klien protokol PostgreSQL sendiri + migrasi SQL | `server/src/db/pgwire.ts`, semua SQL di `repo.ts` |
| Klien Redis | Klien RESP sendiri | `server/src/cache/resp.ts` |
| Vite | esbuild | `scripts/build-client.mjs` |

PostgreSQL 16 dan Redis 7 yang dipakai adalah server asli. React dan TypeScript sesuai permintaan.

Keputusan yang perlu Anda ambil sebelum M2: tetap dengan implementasi ini, atau porting ke Phaser/Colyseus/Prisma di lingkungan yang punya akses npm. Porting renderer ke Phaser paling masuk akal dilakukan sebelum M2, karena M2 menambah banyak kode sprite dan animasi.

## 3. Hasil uji (dijalankan, bukan klaim)

**Unit + integrasi: 22/22 lulus** (`npm test`). Integrasi berjalan terhadap PostgreSQL dan Redis asli lewat HTTP dan WebSocket sungguhan.

**Browser (Chromium headless): lulus** (`npm run test:browser`). Daftar akun lewat UI, buat karakter, jalan 1 detik (160 px, 0 koreksi prediksi), pemain kedua terlihat, chat terkirim, reload lalu lanjut di posisi yang sama, tanpa error konsol.

**Uji beban** (`npm run load`), 60 detik per putaran, bot jalan acak dengan 20 input/detik, mesin 2 core, bot dan server di mesin yang sama:

| Klien | Tick rate | Tick avg | Tick p99 | Tick maks | Tick terlambat | Putus | Unduh per klien |
|---|---|---|---|---|---|---|---|
| 20 | 20 Hz | 0,46 ms | 0,83 ms | 2,7 ms | 0 | 0 | 30 kbps |
| 100 | 20 Hz | 2,4 ms | 4,4 ms | 6,9 ms | 0 | 0 | 128 kbps |
| 250 (2 channel) | 20 Hz | 6,2 ms | 10,9 ms | 14,1 ms | 0 | 0 | 153 kbps |

Anggaran per tick adalah 50 ms.

Yang **belum** terbukti:
- FPS klien 60 hanya terbaca di Chromium headless dengan 2 pemain. Belum diukur di GPU nyata atau dengan layar penuh pemain.
- Uji beban lewat loopback; latensi dan packet loss internet belum disimulasikan.
- Docker (`deploy/`) ditulis tapi belum pernah dijalankan; tidak ada daemon Docker di sandbox.

## 5. Keterbatasan yang diketahui

- Seni adalah placeholder prosedural yang digambar kode. Pipeline aset (bagian 16 prompt) dijadwalkan M8. Catatan: saya tidak bisa menghasilkan spritesheet raster hasil lukisan; opsinya pixel art prosedural/SVG dari saya, atau aset dari artis/alat gambar yang diimpor lewat pipeline.
- Hanya 2 dari 6 region. Belum ada NPC, monster, combat, inventory, party (M2–M8).
- Job baru berupa identitas dan tampilan; belum ada stat atau skill.
- Protokol JSON. Pada 25+ pemain terlihat, bandwidth per klien di atas 120 kbps; encoding biner direncanakan di M9.
- Satu proses server. Redis sudah dipakai untuk sesi dan rate limit, tapi room belum bisa dibagi antar proses.
- Belum ada lag compensation (tidak relevan sebelum combat).
- `GET /api/metrics` terbuka tanpa autentikasi; tutup di reverse proxy sebelum produksi.
- TLS diharapkan dari reverse proxy; server sendiri HTTP/WS polos.
- Rate limit per IP memakai alamat socket; di belakang proxy perlu membaca `X-Forwarded-For`.
- `types/shims.d.ts` menggantikan `@types/react` dan `@types/ws`; hapus setelah `npm install`.

## 6. Menjalankan

```bash
npm install                    # di mesin dengan akses npm
./scripts/dev-services.sh      # PostgreSQL + Redis lokal
npm run build && npm start     # http://localhost:8080
npx tsx scripts/seed.ts        # opsional: akun demo / demo-password
npm test && npm run test:browser
AUTH_RATE_LIMIT=1000000 npm start &  npm run load -- 100 60
```

Konfigurasi lewat environment: lihat `server/src/config.ts`.
