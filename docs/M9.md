# Aetherion Online — Laporan Milestone 9 dan Laporan Akhir (Playable Alpha)

Versi: **0.9.0-alpha**. Semua angka di dokumen ini berasal dari pengujian yang dijalankan di lingkungan pembuatan (mesin 2 core; server, database, dan klien uji berjalan di mesin yang sama).

## Ringkasan jujur

- **Game bisa dimainkan** dari daftar akun sampai membunuh boss dungeon bersama party, dan semua itu tersimpan di PostgreSQL. Ini dibuktikan oleh tes otomatis, bukan klaim.
- **Stack yang diminta tidak dipakai sepenuhnya.** Phaser, Colyseus, Prisma, Vite, dan pustaka klien Redis tidak bisa dipasang (akses jaringan untuk instalasi paket mati di akun ini). Penggantinya ditulis tangan dan diuji; lihat bagian 2.
- **Seni dibuat dari kode.** Tidak ada alat pembuat gambar di sesi ini. Pipeline impor dengan validasi sudah ada sebagai jalur masuk aset sungguhan.
- **Belum pernah dimainkan manusia.** Semua verifikasi adalah tes otomatis dan klien bot. Keseimbangan di atas level 10 berasal dari rumus.
- **Docker belum diverifikasi.** Jalur produksi tanpa Docker sudah diverifikasi dari awal sampai akhir.

## 1. Yang dikerjakan di M9

### Performa

- Replikasi snapshot ditulis ulang: potongan JSON per entitas dibuat sekali dan dipakai bersama oleh semua penonton; versi gerak dan versi vital digabung ke satu map.
- **Entitas di luar layar** (di dalam area minat 1600×1040 tetapi di luar layar maksimum 1280×720) dikirim seperempat laju dan tanpa angka damage. Tetap akurat saat masuk layar (teruji).
- Hasil terukur dengan benchmark in-process: **bandwidth turun 14–17%**; **CPU tidak berubah berarti** (±3%, dalam derau). Saya melaporkannya apa adanya: optimasi CPU-nya tidak menghasilkan percepatan yang terukur.
- Alat ukur baru: `scripts/bench.ts` (simulasi tanpa jaringan), `scripts/capacity.sh` (ramp dan soak), `scripts/fps-crowd.ts` (FPS klien di tengah keramaian).

### Keamanan

| Area | Yang ditambahkan di M9 |
|---|---|
| Metrics | `/api/metrics` butuh token Bearer (`METRICS_TOKEN`, dibandingkan constant-time); tanpa token hanya bisa dari loopback |
| Alamat klien | `X-Forwarded-For` hanya dipakai jika `TRUST_PROXY` diset, dan hanya entri dari proxy tepercaya; klien tidak bisa memalsukan alamatnya |
| WebSocket | Cek `Origin` saat handshake (situs lain tidak bisa membuka socket dengan sesi pemain); batas koneksi total dan per alamat |
| Header | CSP (`script-src 'self'`, tanpa inline script), `X-Frame-Options: DENY`, `Referrer-Policy`, `nosniff` di semua respons |
| HTTP | Body terlalu besar dijawab 413 dengan benar (sebelumnya koneksi diputus tanpa jawaban) |

Yang sudah ada dari milestone sebelumnya dan diuji ulang: server-authoritative untuk semua aksi, anggaran input (anti speed-hack), rate limit pesan per socket, payload maksimum 1 KB, timeout join 5 detik, rate limit login per alamat, password scrypt, token sesi disimpan sebagai hash, SQL berparameter, validasi semua data tersimpan saat dimuat, path traversal ditolak.

### Deployment

- Server dibundel jadi satu file (`dist/server.mjs`) yang jalan di Node biasa.
- `scripts/verify-deploy.sh` memverifikasi jalur produksi dari database kosong sampai shutdown bersih. Detail di `docs/deploy.md`.
- File Docker, systemd, nginx, dan `.env.example` diperbarui (Docker/systemd/nginx **belum dijalankan**).

Anggaran satu tick adalah 50 ms. Cara membacanya:

- **Sampai 200 klien**, tick terburuk masih di bawah anggaran.
- **Pada 250 dan 300 klien**, ada tick tunggal yang melewati 50 ms (50,7 dan 69,4 ms). Loop tidak pernah tertinggal (0 tick terlambat, tidak ada koneksi putus), tetapi ini berarti sesekali ada jeda yang terasa. Saya **tidak mengklaim 250+ klien bebas hambatan**.
- Bot berjalan di mesin 2 core yang sama dengan server dan database, jadi angka ini batas bawah.
- Bot berkumpul di sekitar plaza Eldoria. Bandwidth 160–225 kbps per klien di keramaian itu **tinggi** untuk game 2D; penyebab utamanya protokol JSON.

**Kapasitas yang berani saya nyatakan: sekitar 150–200 pemain serentak per proses** pada mesin sekelas ini.

## 5. Keterbatasan yang diketahui (keseluruhan)

**Belum diverifikasi**
- Permainan oleh manusia; keseimbangan; rasa kontrol dan kamera.
- Docker, systemd, nginx, TLS, jaringan internet sungguhan (latensi, packet loss).
- FPS di perangkat keras nyata; perilaku di ponsel atau layar sentuh (tidak ada kontrol sentuh).
- Stabilitas lebih dari 10 menit; lebih dari 300 klien.

**Belum ada**
- Quest, reputasi faksi, guild, trade antar pemain, auction house, bank, PvP, pet, mount.
- Suara dan musik.
- Peta dunia, tutorial, pengaturan (key binding, volume, bahasa).
- Reset password, verifikasi email, moderasi (lapor, mute, ban), panel admin.
- Skala horizontal (banyak proses), pindah antar server, backup otomatis.
- Impor layer karakter, tileset, dan ikon lewat pipeline aset.

**Kelemahan teknis**
- Protokol JSON boros bandwidth (160–225 kbps per klien di keramaian). Protokol biner akan memangkasnya beberapa kali lipat.
- Replikasi berbiaya kuadratik saat semua pemain saling melihat.
- Monster tidak punya pathfinding dan bisa tersangkut.
- Ability area membidik target, bukan kursor.
- Party hanya di memori (hilang saat server restart).
- Klien database, Redis, dan room server adalah kode buatan sendiri yang jauh kurang teruji dibanding pustaka yang diminta.
- Seni prosedural: konsisten dan terbaca, tetapi bukan karya ilustrator.
