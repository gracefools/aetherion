# Aetherion Online — Milestone 12: Skill Icons, Rune Scrolls and Asset Pipeline

Version **0.12.0-alpha**.

## 1. Honest summary

- **Icons:** 112 original icons, drawn by code: one for each of the 49 active abilities, 25 status effects, 11 weapon attacks, 5 runes and 22 passives. No emoji, no letters, no shared placeholder; a test checks that no two are the same picture. They are **code-drawn vector symbols, not illustrations**: consistent and readable, but an artist would do better, and nobody has judged them by eye. Each can be replaced by a PNG through the asset pipeline with no code change (tested in the browser).
- **Passive icons are the weakest part:** the 49 active abilities each have a symbol designed for them; the 22 passives get a sigil derived from their id (each different, but not meaningful).
- **Runes are now collected.** A new character owns no rune. Runes come from the Rune Merchant, from Rune Scrolls, and from monster, elite, dungeon boss and world boss drops. Characters created before this change keep every rune they had attuned or levelled.
- **Quest and event rewards** for scrolls are not built: there are no quests or events yet (M13).
- **Asset pipeline:** extended to icons, NPC sheets, tilesets and effect strips, with derived metadata. **Only icons are loaded by the game from imported files** (as monsters and map objects already were). NPC sheets, tilesets and effects are validated and described, but the renderer does not use them yet; character layers were already in that state.

## 2. Skill icons (12.1)

`client/src/game/skillicons.ts`. One size, 64×64, with transparent corners; smaller UI sizes are resampled once and cached. One visual language: a framed tile tinted by element or class, a bold outlined symbol, a soft highlight. Rune spells have a pale gold rim, job skills a gold rim, passives grey; status icons have a **red rim for debuffs and a green rim for buffs**; rune icons are hexagonal stones.

Shown on the hotbar, in the skill book (skills and rune spells), on status chips, in the auto hunting panel's skill list and in the Rune Merchant's shop.

The **skill icon manifest** is `iconManifest()` in code and `assets/templates/icons/icons.json` on disk: for each icon its id (`skill/fireball`), kind, the skill, status, weapon or rune it belongs to, name, file and size. `npm run assets:export` writes all 112 as PNG templates.

## 3. Rune acquisition (12.2)

Three ideas, kept separate:

| | Meaning | Where |
|---|---|---|
| Owning | The rune has been obtained | `build.runes.lv[element] >= 1` |
| Equipping | The rune is in a rune slot (unchanged attunement) | `build.runes.slots` |
| Upgrading | The rune's level grows with experience | casting, and spare scrolls |

Attuning a rune the character does not own is refused by the server ("You do not own that rune yet").

| Source | What |
|---|---|
| Ordinary monsters | Random Rune Scroll, 1.2% per kill |
| Elite monsters | Random Rune Scroll, 15% per kill |
| Dungeon bosses | Advanced Rune Scroll (Normal, Hard), Rare Rune Scroll (Nightmare), for everyone rewarded |
| World bosses | Rare Rune Scroll |
| Rune Merchant | The five runes; Random and element scrolls |
| Quests and events | Not built (M13) |

## 4. Rune Merchant (12.3)

One in every town (six NPCs, named). Talk with **F**. Five categories (Fire, Water, Wind, Earth, Lightning); for each: icon, description, element, the spells it grants with their effects, required level, price, and whether it is owned. Buying takes a confirmation. Paid in gold.

Prices and level requirements are data (`RUNE_SHOP` in `shared/src/runes.ts`): Fire and Water 400 gold (level 1), Wind 450 (level 3), Earth 500 (level 5), Lightning 600 (level 8). **A character's first rune is free**, so nobody is locked out of magic for lack of gold. The server checks distance to the merchant, level, gold and ownership.

## 5. Rune Scrolls (12.4)

Eight inventory items: Fire, Water, Lightning, Earth, Wind, Random, Advanced and Rare Rune Scroll. They stack, can be traded and sold, and are read from the bag with a confirmation.

| Scroll | Result |
|---|---|
| Element scroll | That rune |
| Random | One of the five, equal chances |
| Advanced | One of the five; a new rune arrives with 60 experience; 150 experience if already owned |
| Rare | Always a rune not yet owned, with 120 experience; 300 experience if all five are owned |

Reward tables are data (`SCROLLS`). Rules enforced by the server:

- reading consumes exactly one scroll and applies the reward in the same step, so a scroll cannot be read twice and cannot be duplicated;
- **an owned rune is never overwritten**: it gains experience instead, and the player is told which happened;
- a scroll on the table in a trade cannot be read;
- the dead cannot read.

## 6. Asset import pipeline (12.5)

One folder, one manifest: an asset is its file plus one entry in `assets/game/manifest.json`. Nothing else is edited.

| Type | Format | Loaded by the game |
|---|---|---|
| `monster` | 13×2 frames | yes (since M8) |
| `prop` (map objects) | 32×32 | yes (since M8) |
| `character` layers: body, clothing, armor, face, hair, helmet, accessory, cape, weapon | 4 rows, all animations | validated only (since M8) |
| `icon`: skill, passive, status, attack, rune, item | 64×64 (items also 16 or 32) | **yes** (new) |
| `npc` | a full character sheet, four directions | validated only (new) |
| `tileset` | a grid of 16 or 32 pixel tiles | validated only (new) |
| `vfx` | one row of frames, with frame size, count and fps | validated only (new) |
| audio | OGG, own manifest | yes (M10) |

**Metadata** is derived by the validator for every asset that passes and written into the build's manifest: asset id, type, source file, width and height, frame dimensions, animation names with frame counts, direction of each row, layer order, anchor, transparency, frame rate, the character, class, monster or skill it belongs to, source and licence. Only source and licence have to be typed (and are required for the new types).

**Reported faults:** missing files; invalid dimensions; incorrect sprite frame sizes; missing animation directions; duplicate asset ids; unsupported formats (anything but PNG, and a file that is not really a PNG); missing metadata; plus names not in the game data, wrong folders, missing transparency, empty frames, and PNG files that no entry lists. An asset with any error is left out of the build; the rest ship.

## 8. Tests

Type check 0 errors; **144 / 144** unit and integration; browser test passed.

New: rune ownership and the three separate concepts, including characters saved before M12; scroll tables (5,000-sample distribution, the Rare scroll's preference), reading, double use, no overwrite; the Rune Merchant (in every town, first rune free, price, level, distance, ownership, scroll stock); drop rates over 20,000 kills and boss scrolls; icons (every ability has a designed symbol, manifest complete, all 112 exported files different, 64×64, transparent corners); the pipeline (every rule for the four new types, derived metadata, a folder with seven kinds of fault, import). In the browser: icons distinct in the page and on the hotbar, a rune bought with confirmation, a scroll bought, read and consumed, the rune attuned as a separate step, and an imported icon replacing the built-in one pixel for pixel.

Three existing tests were updated for intended rule changes: attuning now needs ownership (two places), towns have a fourth NPC, and a kill with every drop chance forced yields four items instead of three.

## 9. Remaining risks

- **Balance:** scroll drop rates and rune prices are first guesses.
- **New characters start without runes.** The first is free at the Rune Merchant, but a new player has to find that out; there is no tutorial yet (M16).
- Icons were checked for being different, not for being good.
