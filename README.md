# Aetherion Online

An original browser-based, real-time 2D MMORPG: server-authoritative multiplayer, six jobs, rune magic, parties, six regions, instanced dungeons, bosses and world bosses, loot up to Mythic, dynamic music and sound, auto hunting, collectible runes, player trading, quests and factions, guilds, a bank and an auction house, PvP with duels and an arena, pets and mounts, a world map, a tutorial, rebindable keys, and an English and Indonesian interface. **Playable alpha** (version 0.18.0-alpha, milestones M1–M16).

No energy, stamina, keys, daily limits or lockouts anywhere in the game.

**Read first:** [DEVELOPMENT_PROGRESS.md](DEVELOPMENT_PROGRESS.md) tracks the extended milestones (M10–M18): status, what is and is not done, known bugs, test results and next tasks. ## Quick start

```bash
npm install
./scripts/dev-services.sh        # local PostgreSQL 16 + Redis (Debian/Ubuntu)
npm run build && npm start       # http://localhost:8080
```

With Docker only (no Node, PostgreSQL or Redis on the machine; this is how it was run and tested on Windows):

```bash
# deploy/.env needs two lines: POSTGRES_PASSWORD=<your choice> and METRICS_TOKEN=<long random string>
docker compose -f deploy/docker-compose.yml up -d --build      # the game on http://localhost:8080
# tests and tools, in a container with Node, PostgreSQL 16, Redis, ffmpeg and Chromium:
docker build -t aetherion-dev -f deploy/Dockerfile.dev .
docker run --rm -v "${PWD}:/app" -v aetherion_node_modules:/app/node_modules aetherion-dev bash -c "npm run build && npm test && npm run test:browser"
```

Production (one bundled file on plain Node; see [docs/deploy.md](docs/deploy.md)):

```bash
npm run build:all
DATABASE_URL=... REDIS_URL=... METRICS_TOKEN=... npm run start:prod
./scripts/verify-deploy.sh       # end-to-end check of exactly this path
```

## What is in the game

- **Accounts and characters:** register, log in, up to four characters, creator with 22 appearance options.
- **Six jobs:** Knight, Mage, Ranger, Assassin, Cleric, Berserker. Two weapon specialisations each, skill trees, 50 abilities.
- **Rune magic:** five elements, twelve spells, rune levels that grow with use.
- **World:** Eldoria, Verdant Reach, Ashen Highlands, Frostveil, Dreadmoor, Astral Ruins. Towns with a merchant, a waystone keeper (fast travel) and a lorekeeper; resource nodes; hidden caches.
- **Combat:** 40 monster types with telegraphed attacks, status effects, threat, elites.
- **Parties:** up to five, shared EXP, party chat, three loot modes.
- **Dungeons:** four instanced dungeons (waves, elite, boss), three difficulties, scaled for one to five players.
- **Bosses:** six bosses with phases, enrage and unique mechanics; two are world bosses with contribution-based rewards.
- **Items:** six rarities, five equipment slots, upgrades to +10, four sets, six unique passives, crafting.
- **Audio (temporary placeholder assets):** 16 music tracks chosen by where you are and what is happening (menu, each region, villages, combat, elites, dungeons, bosses, victory, defeat) with crossfades and seamless loops; 67 sound effects (footsteps by surface, weapons, a distinct sound for each of the twelve rune spells, items, loot rarities, bosses, UI); 5 ambience loops; audio settings saved to the account.
- **Auto hunting:** attack, skills by priority with conditions, potions at thresholds, loot rules, a hunting radius; the server validates every action and keeps the session's figures. No time or energy limit.
- **Runes are collected:** from the Rune Merchant in every town (the first is free) and from Rune Scrolls dropped by monsters and bosses.
- **Trade and bag tools:** secure player-to-player trading of items and gold with an audit log; bulk sale; sorting.
- **Icons:** 112 original icons for skills, statuses, weapon attacks and runes.
- **Persistence:** everything above is stored in PostgreSQL.

## Honest summary of the gaps

- The requested stack (Phaser, Colyseus, Prisma, Vite, a Redis client library) could not be installed where this was built. Hand-written equivalents are used and tested; see docs/M9.md, section "Stack".
- All art is generated by code. An import pipeline with validation exists; no artist-made or generated images are included.
- All audio is a temporary stand-in synthesised by code, not the Suno-generated soundtrack the specification asks for, and nobody has listened to it critically: it was checked by measurement and automated tests only.
- Balance above level 10 comes from formulas, not from play sessions.
- Docker Compose has now been run (on Docker Desktop for Windows); the systemd and nginx files were not.
- One server process, no horizontal scaling.

## Sharing the game over the internet with ngrok

1. Start the game: `docker compose -f deploy/docker-compose.yml up -d`.
2. Make sure `deploy/.env` contains `TRUST_PROXY=1` (then run step 1 again). Behind ngrok every connection comes from ngrok's address; with this setting the server reads each player's real address, so its per-address connection and sign-in limits apply per player and not to everyone at once.
3. Sign ngrok in once: `ngrok config add-authtoken <your token>`.
4. Run `powershell -ExecutionPolicy Bypass -File deploy\ngrok.ps1` (add `-Domain your-name.ngrok-free.app` for a reserved domain). Share the `https://…` address it prints.

No other change is needed: the page connects to the game socket over `wss://` on the same address, and the server accepts it because the page and the socket share that address. On ngrok's free plan, visitors first see ngrok's warning page once and click **Visit Site**. Anyone with the address can create an account and play while the tunnel runs; stop it with Ctrl+C. With `TRUST_PROXY=1`, connect players only through ngrok (or localhost): someone on your local network reaching port 8080 directly could send a false address.
