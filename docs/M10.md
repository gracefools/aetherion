# Aetherion Online — Milestone 10: Audio, Music and Sound Effects

Version **0.10.0-alpha** when written. Scope: section M10 of the extended specification.

> **Changed since (0.12.0-alpha):** the normal combat track was rewritten to be more intense (172 bpm), the elite track raised to 184 bpm, and a battle-start impact sound added, so the build now ships 89 audio files (9.82 MB) and 68 effects. The figures in section 6 are from the original 88-file build. The monster navigation fix, M11 and M12 are reported in their own documents (see `DEVELOPMENT_PROGRESS.md`).

## 1. Honest summary

- **The audio system is real and complete**: a Web Audio engine in the client, dynamic music driven by what the server tells each client, positional sound effects, ambience, settings saved to the account in PostgreSQL, and a validated asset pipeline. It is covered by unit, integration and real-browser tests.
- **The audio itself is temporary.** The specification asks for original music made with the **Suno MCP integration**. I checked first: no Suno MCP server (or any music-generation tool) is connected to the environment this was built in. Following the specification's own rule for that case, I did not pretend, and did not quietly use another provider. All 88 sounds are original stand-ins **synthesised by this project's own code**, and every one is labelled temporary in the manifest and in the game's settings panel.
- **Nobody has listened to this audio.** I cannot hear. Everything was verified by measurement (levels, loop seams, durations, file validity) and by automated tests that the right sound plays at the right moment. Whether it *sounds good* is unverified, and the music in particular is simple synthesiser music, not a produced soundtrack. Please listen and judge.
- **Nothing is cleared for commercial use.** The placeholders contain no third-party material, but no rights review of any kind was done.

## 3. What was built

### 3.1 Dynamic music (specification 10.3)

Each client decides its own music from authoritative state: the zone in the server's welcome message, the player's server-reconciled position, damage events, the auto-attack flag, and the monsters the server has put in view. No music instruction is sent over the network. The decision logic is a pure class (`MusicDirector`, `shared/src/audio.ts`) so it is unit-tested without a browser.

| Requirement | How it works |
|---|---|
| Location-based music | One theme per region; one for all dungeon interiors; one for villages. |
| Smooth transition between areas | 1.8 s crossfade. The new track is decoded first; the old one keeps playing until it is ready. |
| Combat music when combat starts | The first damage dealt or taken (or the server reporting auto-attack) switches to combat in 0.6 s. |
| Elite and boss music | A fight involving an elite uses the elite track and stays on it until the fight ends. A living boss within 520 units, or one already engaged anywhere in view, takes over: one track for dungeon bosses, another for world bosses. |
| Return to exploration | After the 5 s combat timeout plus a 3 s linger, a 2.5 s crossfade back. **The region theme resumes where it stopped** instead of restarting. |
| Loops without gaps | Tracks are decoded to memory and looped sample-exactly by the browser. The synthesiser folds each track's tail back onto its start, and every loop's seam is measured (section 6.3). |
| Fade in, fade out, crossfade | All track changes are gain ramps; nothing starts or stops abruptly. |
| Preloading and caching | Entering a zone decodes its theme, the village theme and the combat tracks ahead of need. Decoded music is cached (64 MB budget, least recently used released). Files are requested by content hash and cached by the browser for good. |
| No restart between nearby zones | Asking for the track that is already playing is a no-op. Village music has an inner boundary (10 tiles) to start and an outer one (14 tiles) to stop, so pacing around the edge never switches. Eldoria is one music region. Back-to-back fights are one stretch of combat music. |
| Independent clients, authoritative state | See above. |

Priority, highest first: menu → death → boss → victory fanfare → combat (elite or normal) → special event → dungeon → village → region.

### 3.2 Sound effects (specification 10.4)

67 effects. All are triggered by server events except the player's own footsteps (which follow client-side movement prediction) and UI clicks.

| Group | Trigger |
|---|---|
| Footsteps: grass, stone, snow, water; running layer | The tile under the player and the region's theme: paved tiles are stone, Frostveil is snow, Dreadmoor and the Abyssal Temple are wet. Nearby players' steps are heard quietly and positioned. |
| Weapons: sword swing/impact, greatsword impact, dagger, bow release, arrow impact, staff | The weapon the attacker actually holds. Other players' swings come from the server's attack events. |
| Shield block, physical hit, critical hit, monster hit, monster death, player damage, player death | Flags and targets of the server's damage and health events. |
| Rune magic: 14 sounds for the 12 spells | The server's cast and effect events. Every spell has its own sound; Fireball has a launch and an impact; Meteor Strike has a falling sound during its cast and an impact. A test asserts no two spells share a sound. |
| Job skills: 11 sounds | By effect type (shout, buff, heal, barrier, dash, smoke, trap set/sprung, arcane, holy, volley); slash skills use the weapon's own swing. |
| Potion, pickup, gold, equip, upgrade success/failure, Rare/Legendary/Mythic drop | The server's inventory, loot and upgrade messages. |
| Level up, dungeon entrance, boss appears, boss defeated, World Boss announcement, portal, gathering, cache | The corresponding server messages and cues. |
| UI click, notification, refusal | Any button, tab or menu; announcements and invitations; refused actions. |

Sounds from other entities are positional (quieter with distance, panned left/right, silent beyond 560 units).

**Server change:** notices from the server now carry an optional `cue` (`boss`, `worldboss`, `bossdown`, `phase`, `stage`, `clear`, `loot`, `upgrade_ok`, `upgrade_fail`, `cache`, `attune`). The server names the event; the client picks the sound. Without this the client would have had to guess from message text.

### 3.3 Ambience

Five loops (city, forest, dungeon, wind, marsh water) on their own bus with their own volume slider, crossfaded like music.

### 3.4 Settings (specification 10.6)

Press **O** in game, or the **Settings** button on the sign-in and character screens.

- Master, music, sound-effect and ambient volume; mute all; music on/off; sound effects on/off.
- Applied immediately. Saved to this browser, and — when signed in — to the account in PostgreSQL (`account_settings`, migration 006) through `GET`/`PUT /api/settings`. The account's copy wins when you sign in on another device.
- The server validates every value (range, type, unknown keys refused) and cleans stored data again when reading it.

**Browser autoplay rules:** no audio context is created and nothing is downloaded until the first click, tap or key press. If the page loads straight into the game (a saved session), a small banner says "Sound is off until you click or press a key" with an **Enable sound** button; it disappears on the first interaction.

### 3.5 Asset pipeline (specification 10.5)

```
assets/audio/
  manifest.json        one entry per sound (see below)
  music/     menu city village forest volcano snow swamp ruins combat dungeon boss events
  sfx/       movement combat rune monsters items ui environment
  ambience/  city forest dungeon weather water
```

All files are OGG Vorbis. Each manifest entry records: asset id, file path, category, title, **measured** duration, loop flag, volume normalisation (`gain`), trigger event, associated map/monster/class/skill, location and mood (music), channels, sample rate, peak and RMS level, provider, source and provenance, generation date, licence and usage-rights notes, and whether it is temporary.

`scripts/import-audio.ts` runs in every client build. It validates the folder against the manifest and against the game's sound catalogue, and copies only what passes. It rejects: missing files, anything that is not really an Ogg stream, a stated duration that is not the file's real duration, duplicate ids or files, missing metadata, a loop flag or category that contradicts how the game uses the sound, paths outside the folder, and **a temporary placeholder described as commercially cleared**. Sounds the game needs but the manifest lacks are reported one by one.

WAV masters: the placeholders are deterministic, so `npm run audio:build -- --wav <dir>` regenerates 16-bit WAV masters at any time; they are not stored in the repository.

## 5. Deviations from the specification

- **"Colyseus", "Phaser", "Prisma"**: as documented in `docs/M9.md`, the project uses its own room server, canvas renderer and PostgreSQL client. M10 follows the project as it is: audio uses the Web Audio API directly, and the settings table is a plain SQL migration.
- **Running sound**: implemented as a faster cadence plus a light gear/cloth layer over the surface footstep, not as separate running samples per surface.

## 6. Measurements

Run on 2026-11-17 in the dev container (`deploy/Dockerfile.dev`: Node 22, PostgreSQL 16, Redis, headless Chromium with software rendering) on Docker Desktop for Windows.

### 6.1 Tests

| Suite | Before M10 | After M10 |
|---|---|---|
| `tsc -p .` | 0 errors | 0 errors |
| Unit + integration | 110 / 110 | **121 / 121** (9 new unit tests, 2 new integration tests) |
| Browser end-to-end (Chromium, two players) | passed | **passed**, with a new audio section |

What the new tests prove:

- **Unit:** settings sanitising and bus gains; the 16-track catalogue and folder structure; one sound identity per rune spell and a real sound for every ability, weapon and surface; the music director (regions, village boundary, combat linger, grinding does not flap, elite, bosses, death, victory, zone change); positional volume and pan; every asset is a valid measured OGG labelled temporary; each validation rule rejects its fault; the import ships only valid files; server cues.
- **Integration (real PostgreSQL, Redis, HTTP):** settings need a session, default to the defaults, are stored per account, survive sign-out, reject 12 kinds of bad input without changing anything, are cleaned when a stored row is damaged, and are rate limited; audio files are served as `audio/ogg`, cached for good by content hash, and path traversal is refused.
- **Browser (the real page):** audio unlocks on the first interaction; each of the six regions plays its own track and ambience; the village theme starts inside the village and does not switch just outside it; real attacks start combat music with weapon and hit sounds; the city theme resumes where it stopped; Fireball is heard leaving and landing and Water Bolt sounds different; an elite switches to the elite track; a boss to the boss track; its death plays the boss-defeat sound and the victory theme, then the city returns; the world boss has its own track; death plays the defeat theme; the settings panel's sliders and switches change the mixer at once, nothing plays while muted, and the settings reach PostgreSQL; after a reload with the browser's own copy deleted, the settings come back from the account, no audio context exists before an interaction, the prompt is shown, and pressing it starts audio.

One existing browser-test step was made robust rather than changed in meaning: the party health check now starts from the member's current health instead of assuming full health (a wound-up area attack from a removed test monster could land first; the server logic is unchanged).

### 6.2 Cost (from the browser test, whole session across all six regions)

| Measure | Value |
|---|---|
| Audio shipped | 88 files, 9.86 MB |
| Decoded music and ambience held in memory | 60.9 MB at the end (budget 64 MB; 61 tracks were released and re-decoded while the test hopped between every region) |
| Decoded effects held in memory | 11.0 MB (all 67) |
| Decode time per file | average 206 ms, worst 1.4 s, off the main thread, on a 2-core machine also running the server, the database and software rendering |
| Effects played / skipped by the same-sound limit / dropped by the 24-voice cap | 222 / 108 / 0 |
| Frame rate reading with audio running | 53–56 fps (the M9 report measured 58–60 in the same kind of environment; the baseline run here read 35, so this reading is noisy and shows no slowdown, not a speed-up) |

A finding during testing, and the fix: the first version decoded all 88 files as soon as audio unlocked. On this 2-core machine that made the first second of play stutter enough to fail a timing-sensitive step of the existing browser test. Loading now goes through a priority queue (needed now → likely next → background warm-up, one at a time with pauses), and the stutter is gone. On the 64 MB figure: it is a cap, not a leak, but it is the largest memory cost the client has. Typical play in one region holds three or four tracks (30–45 MB).

### 6.3 Loop seams (`npm run audio:verify`)

Each looping file is decoded from its OGG and the step from its last sample back to its first is compared with the steps inside the track. All 19 loops (14 music, 5 ambience) join within the range of their own normal sample-to-sample movement: the largest seam is 0.81 of the track's own 99.9th-percentile step. No loop clicks. Encoded length equals rendered length to the sample for all 88 files (the build fails otherwise).

### 6.4 Levels

Music is normalised to −20 dBFS RMS with peaks under −3 dBFS; ambience to −24 dBFS RMS; effects to a −3 dBFS peak and then scaled per sound by the manifest's `gain` (0.1 for the running layer up to 0.95 for the meteor impact).

## 8. Replacing a placeholder with a real track

1. Encode the track as OGG Vorbis (or Opus) and save it over the placeholder's path, e.g. `assets/audio/music/city/bgm-002-eldoria-main-city.ogg`.
2. In `assets/audio/manifest.json`, update that entry: `duration` (the validator tells you the real one), `provider`, `source` (prompt, tool, version), `generated`, `license` (what the terms actually grant), and set `temporary` to `false`.
3. `npm run audio:check`, then rebuild. For a looping track, `npm run audio:verify` reports whether its loop point clicks.

No code changes. A track meant to loop must be exported so its end leads back into its start.

## 9. Before any commercial use

Not verified by me, and it must be before release:

- The Suno plan in force when each track is generated, and what its terms say about commercial use and ownership of output. These terms differ by plan and change over time.
- Any distribution restrictions (for example, on releasing the music separately from the game).
- That prompts used no artist names, existing soundtracks, copyrighted melodies or lyrics as references.
- AI generation does not guarantee a track can never receive a copyright claim. Keep each track's prompt, date and account in the manifest so a claim can be answered.

The validator will not accept a file marked temporary whose licence text claims commercial clearance. It cannot check a claim on a non-temporary file: that is a human's signature.

## 11. Remaining risks

- **Sound quality is unjudged** (section 1). The effect volumes relative to each other were set by estimate; expect to adjust `gain` values in the manifest after listening.
- **Loudness on real speakers** is unknown. A limiter on the master bus prevents clipping, but balance between music and effects at the default settings is a guess.
- **Mobile**: untested. The game has no touch controls anyway.
- **Many players fighting on screen**: voices are capped at 24 and the same sound cannot restart within 55 ms, so cost is bounded, but what a 50-player fight *sounds* like is untested.
