# Aetherion Online — Laporan Milestone 2 (Enam Job & Character Creator)

Status: **M2 selesai dan teruji** di atas stack M1 (lihat penyimpangan stack di `docs/M1.md`; tidak berubah). M3–M9 belum dikerjakan.

## 1. Yang dibangun

| Area | Implementasi |
|---|---|
| Enam job | Knight, Mage, Ranger, Assassin, Cleric, Berserker. Masing-masing punya atribut dasar dan pertumbuhan sendiri, stat turunan, 2 spesialisasi senjata, 3 pasif, skill tree 7 node dalam 3 tier, dan 3 tingkat progresi job. Semua didefinisikan di `shared/src/jobs.ts` |
| Stat otoritatif | Server menghitung stat dari job + level + senjata dan mengirimnya saat masuk. Klien tidak pernah mengirim stat |
| Perbedaan mekanik yang sudah aktif | Kecepatan gerak per job (Assassin tercepat, Knight terlambat), interval serangan per job dan senjata, sumber daya Rage untuk Berserker (mulai 0, batas tetap 100), pasif stat aktif sesuai level |
| Character creator | 22 opsi: presentasi gender, postur, tinggi, kulit, wajah, gaya mata, warna mata, rambut, warna rambut, pakaian + 2 warna, armor, helm, senjata (sesuai job), jubah, aksesori, warna masing-masing, efek aura. Pratinjau animasi untuk 7 gerakan dan 4 arah, tombol acak |
| Sprite modular | 9 lapisan (body, clothing, armor, face, hair, helmet, accessory, cape, weapon) + aura saat render. Tiap lapisan bisa dirender terpisah |
| Animasi | idle, walk, run, attack, cast, hit, death × 4 arah = 96 frame per karakter |
| Gerak | Lari (default) dan jalan (Shift), kecepatan dihitung server. Tidak ada stamina |
| Aksi | Space = serang, Q = cast. Server memvalidasi cooldown lalu menyiarkan ke pemain sekitar |
| Sinkronisasi | Pemain lain menerima tampilan dan senjata persis, gaya jalan/lari, dan animasi aksi |
| Persistensi | Tampilan disimpan di PostgreSQL (JSONB dengan constraint versi). Migrasi 002 mengubah karakter M1 ke skema baru |
| HUD | Bar HP dan Mana/Rage, lembar karakter (tombol C): atribut, stat tempur, pasif, skill tree, progresi |

## 2. Hasil uji (dijalankan)

**Unit + integrasi: 31/31 lulus** (`npm test`), 11 di antaranya baru untuk M2:
- Enam job berbeda secara mekanik dan lengkap; prasyarat skill tree valid.
- Identitas job bertahan di level 1, 15, 30, 60 (Knight HP dan defense tertinggi, Mage magic tertinggi, Assassin tercepat, Cleric heal tertinggi, Berserker attack dan lifesteal tertinggi).
- Stat naik tiap level; pasif aktif tepat di levelnya; pilihan senjata mengubah stat.
- Validasi tampilan ketat: tiap field diuji batas atas, negatif, pecahan, string, hilang, dan field asing.
- Kecepatan per job dan jalan/lari diterapkan server; spam serangan dibatasi interval job.
- Lewat jaringan nyata: 22 field tersimpan di PostgreSQL dan diterima pemain lain persis sama.
- Migrasi 002 diuji pada data berbentuk M1.

**Browser (Chromium headless): lulus** (`npm run test:browser`). Membuat karakter lewat semua tab creator, memeriksa data tersimpan, lari 160 px/detik dan jalan 96 px/detik dengan 0 koreksi prediksi, pemain kedua melihat tampilan persis serta animasi attack, cast, dan run, lembar karakter tampil, reload lanjut di tempat, tanpa error konsol.

**Validasi sprite: 30 sheet, 2.880 frame.** Dimensi benar, tidak ada frame kosong, kiri adalah cermin kanan, tiap animasi berbeda dari idle di tiap arah, lapisan bisa diisolasi. Validasi ini menemukan satu cacat nyata (frame serangan Ranger dari depan sama dengan idle) yang lalu diperbaiki.

**Migrasi pada data nyata:** 376 karakter M1 di database dev dimigrasikan, 0 tidak valid.

**Uji beban ulang** (60 detik, mesin 2 core, bot dan server di mesin yang sama):

| Klien | Tick rate | Tick avg | Tick p99 | Tick maks | Terlambat | Putus | Unduh per klien |
|---|---|---|---|---|---|---|---|
| 100 | 20 Hz | 2,6 ms | 5,1 ms | 12,0 ms | 0 | 0 | 148 kbps |
| 250 (2 channel) | 20 Hz | 7,3 ms | 12,7 ms | 22,0 ms | 0 | 0 | 192 kbps |

Lebih berat dari M1 (2,4 ms dan 6,2 ms) tetapi masih jauh di bawah anggaran 50 ms. Bot M2 lebih lambat menyebar sehingga tiap klien melihat lebih banyak pemain (33 dan 40, dibanding 24 dan 33), jadi angkanya tidak sepenuhnya sebanding.

## 4. Keterbatasan yang diketahui

- **Skill belum bisa dipakai.** Skill tree dan pasif berpemicu (misalnya Retribution, Ambush) baru berupa data dan tampilan. Eksekusinya masuk M3 (combat) dan M4 (rune dan skill). Poin skill belum ada.
- **Serang dan cast baru animasi.** Belum ada damage, target, atau biaya mana; itu M3.
- **Hit dan death** hanya bisa dilihat di pratinjau creator sampai combat ada.
- **Equipment yang terlihat berasal dari pilihan creator**, bukan dari inventory. Mengganti equipment dalam game masuk M6. Belum ada cara mengubah tampilan setelah karakter dibuat.
- **Seni masih dibuat oleh kode, bukan dilukis artis.** Setelah revisi seni (lihat bagian 6) tampilannya sudah bergaya pixel art JRPG, tetapi detailnya tetap terbatas dibanding sprite buatan tangan. Kontrak untuk seni impor ada di `docs/asset-pipeline.md`.
- **Angka keseimbangan belum diuji dalam pertarungan**; akan disetel di M3.
- Semua keterbatasan M1 masih berlaku (2 dari 6 region, protokol JSON, satu proses server, Docker belum diverifikasi, FPS belum diukur di GPU nyata).

## 6. Revisi seni (setelah umpan balik "terlihat seperti Paint")

Tidak ada connector MCP pembuat sprite atau pixel art di direktori, jadi seninya ditulis ulang di kode dengan teknik pixel art:

- **Karakter:** proporsi chibi JRPG, frame 48×48, outline gelap 1 px otomatis, ramp tiga tingkat dengan pergeseran hue (bayangan ke ungu, sorotan ke kuning), cahaya dari kiri atas, kepala/rambut/senjata dari mask yang dibentuk manual, rotasi senjata dan animasi jatuh dengan nearest-neighbour (tanpa blur).
- **Dunia:** tekstur rumput, tanah, air, dan batu yang digambar ulang; tepi organik antara rumput, jalan, plaza, dan air; pohon utuh dua lapis sehingga pemain berjalan di belakang tajuk; rumah dengan atap sirap, rangka kayu, jendela, pintu, dan fondasi.
- Server tidak berubah. 31 tes unit/integrasi, tes browser, dan validasi 2.880 frame sprite dijalankan ulang dan lulus; FPS terbaca 60 di Chromium headless.
